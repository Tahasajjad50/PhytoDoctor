1. MIGRATION UTILITY OVERVIEW
--------------------------------------------------------------------------------
The production database migration script (backend/scripts/migrate_sqlite_to_postgres.py)
enables zero-data-loss transitions from SQLite to managed PostgreSQL.
It enforces:
  - Strict topological dependency ordering during schema generation and data transfer.
  - Data type normalization (ISO-8601 strings to PostgreSQL TIMESTAMP/DATE).
  - Explicit record count parity validation between source and target tables.
  - Transaction atomicity with automatic rollback on any insertion failure.


2. STEP-BY-STEP MIGRATION EXECUTION PROCEDURE
--------------------------------------------------------------------------------
Step 1: Execute Dry-Run Validation
  Command:
    python backend/scripts/migrate_sqlite_to_postgres.py --source sqlite:///./backend/phyto_doctor.db --target postgresql://user:pwd@host:5432/phytodoctor --dry-run
  Verifies: Model integrity, table record counts, and target connection reachability.

Step 2: Take Pre-Migration Source Snapshot
  Command:
    python backend/scripts/backup_restore.py --backup
  Output: ./backups/phytodoctor_sqlite_<timestamp>.db

Step 3: Execute Live Target Migration
  Command:
    python backend/scripts/migrate_sqlite_to_postgres.py --source sqlite:///./backend/phyto_doctor.db --target postgresql://user:pwd@host:5432/phytodoctor

Step 4: Post-Migration Parity Verification

3. DISASTER RECOVERY & ROLLBACK PLAN
--------------------------------------------------------------------------------
In the event of an unexpected migration failure or corrupted data state:

A. PostgreSQL Target Rollback:
  - If migration fails during transfer, the script initiates target_session.rollback()
    and Base.metadata.drop_all(target_engine), returning the PostgreSQL database
    to a pristine empty state.

B. Target Restoration via Backup Script:
  - Binary Dump Restore (when pg_restore is available):
    python backend/scripts/backup_restore.py --restore --file ./backups/phytodoctor_pg_<timestamp>.dump --target-url postgresql://...
  - Structured Portable JSON Restore (zero-dependency fallback):
    python backend/scripts/backup_restore.py --restore --file ./backups/drill_export.json --target-url postgresql://...
