1. EXECUTIVE SUMMARY & DIAGNOSTIC SCOPE
--------------------------------------------------------------------------------
This technical diagnosis evaluates the end-to-end software architecture, code
quality, runtime stability, security posture, and data integrity of the Phyto
Doctor enterprise platform. The audit covers all three core components:
  - Mobile Field Client: Flutter / Dart application for Android field agronomists.
  - Backend API: FastAPI / Python 3.11+ REST service with SQLAlchemy ORM.
  - Administration Console: React / TypeScript / Vite web portal for executives.

The system was inspected against production readiness criteria, identifying
critical bottlenecks in persistence durability, credential handling, multi-worker
process concurrency, database dialect compatibility, and user interface parity.


2. COMPONENT-BY-COMPONENT DIAGNOSTIC FINDINGS
--------------------------------------------------------------------------------

A. MOBILE FIELD APPLICATION (FLUTTER / ANDROID)
  1. Ephemeral Storage Vulnerability:
     - Issue: Evidence photographs captured via the camera were initially directed
       to Android's context.cacheDir.
     - Risk: During low-memory conditions, Android OS automatically clears cacheDir
       without notifying running applications. Field officers operating in remote
       areas without immediate cellular connectivity faced catastrophic loss of
       unsynced photographic evidence before synchronization.
     - Status at Diagnosis: Required migration to non-volatile context.filesDir and
       application private storage.

  2. Offline Visit Persistence Architecture:
     - Issue: The mobile client relied on a JSON file journal without native SQLite
       engine backing or transactional write-ahead logging (WAL).
     - Risk: Process termination mid-write could corrupt the JSON payload, rendering
       queued offline visits inaccessible.
     - Status at Diagnosis: Needed native SQLite integration with resilient fallback
       to an atomic write-replace-backup journal architecture.

  3. Credential Sharing Exposure:
     - Issue: When managers shared newly generated field officer credentials via
       the native share sheet, the plain text backend server address
       (https://phytodoctor-api.onrender.com) was included in the message body.
     - Risk: Leaking infrastructure URLs over SMS/WhatsApp creates an unnecessary
       attack surface for reconnaissance and credential probing.
     - Status at Diagnosis: Required immediate omission of the server URL.

  4. Sensitive Credential Exposure in Roster:
     - Issue: Plain text passwords were returned in bulk user listings, allowing
       any supervisory account to view credentials directly on screen without an
       audit trail.
     - Status at Diagnosis: Required password masking with audited, on-demand reveal.


B. BACKEND API SERVICE (FASTAPI / SQLALCHEMY 2.0)
  1. Ephemeral SQLite on Containerized Hosting:
     - Issue: The production deployment blueprint on Render specified an embedded
       aiosqlite database stored on the ephemeral container disk.
     - Risk: Every container restart, redeploy, or auto-sleep cycle completely
       destroyed live database records, wiping accounts, visits, and audit logs.
     - Status at Diagnosis: Mandatory transition to managed PostgreSQL on Render.

  2. SQLite PRAGMA Migration Incompatibility:
     - Issue: Backend startup lifespan unconditionally executed "PRAGMA table_info"
       to run column migrations on the users table.
     - Risk: In a PostgreSQL environment, PRAGMA statements trigger immediate
       syntax errors, crashing the server during initialization.
     - Status at Diagnosis: Required dialect check gating (conn.dialect.name == "sqlite").

  3. Single-Worker In-Memory Rate Limiting:
     - Issue: LoginRateLimiter maintained attempt timestamps in a standard Python
       dictionary in application memory.
     - Risk: In multi-worker Uvicorn configurations, worker processes operate in
       isolated memory spaces. An attacker could bypass rate limits by distributing
       login attempts across worker processes.
     - Status at Diagnosis: Required multi-worker shared rate limiting with Redis
       support and SQLite file-backed cross-process fallback.

  4. Cryptographic Key Coupling:
     - Issue: Symmetric AES-CBC / Fernet data encryption for stored employee
       credentials was derived directly from the JWT SECRET_KEY.
     - Risk: Rotating the JWT signing secret invalidated all encrypted credentials
       in the database, permanently breaking supervisory credential management.
     - Status at Diagnosis: Required dedicated CREDENTIAL_ENCRYPTION_KEY with
       multi-key fallback decryption and token versioning.

  5. API Parameter Name Inconsistency:
     - Issue: React Admin called /performance/employee/{id}/analytics with ?period=
       while the backend strictly expected ?timeframe=.
     - Risk: Caused HTTP 422 Unprocessable Entity errors when admin users filtered
       performance analytics.
     - Status at Diagnosis: Required query parameter aliasing.


C. WEB ADMINISTRATION PORTAL (REACT / TYPESCRIPT / VITE)
  1. CORS Origin Configuration:
     - Issue: Backend allowed localhost:3000 and localhost:5173, but omitted
       production web deployment domains (phytodoctor-admin.web.app).
     - Status at Diagnosis: Required adding production origins to CORS whitelist.

  2. Production Build Parity:
     - Issue: Build scripts required verification to ensure 0 TypeScript compilation
       errors and proper Vite bundling for CDN deployment.
     - Status at Diagnosis: Verified build succeeds with zero errors.


3. BASELINE INTEGRITY & REPOSITORY STATE
