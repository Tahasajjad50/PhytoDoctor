1. POSTGRESQL ARCHITECTURE & COMPATIBILITY VERIFICATION
--------------------------------------------------------------------------------
To resolve the critical risk of ephemeral data loss on Render, PhytoDoctor's
backend has been hardened to support managed PostgreSQL (e.g. Render PostgreSQL,
AWS RDS, Supabase) using SQLAlchemy 2.0 and asyncpg.

A. Dialect DDL Compilation:
All 10 SQLAlchemy ORM models were verified to compile into valid PostgreSQL DDL
syntax using sqlalchemy.dialects.postgresql.dialect():
  1. app_version_config: Valid UUID primary key, timestamp with time zone, boolean.
  2. users: Valid VARCHAR(36) PK, UNIQUE constraints, enum/string roles, timestamps.
  3. refresh_tokens: Foreign key users.id ON DELETE CASCADE, index on token hash.
  4. attendances: Foreign key users.id, check constraints, timestamp awareness.
  5. customers: Foreign key users.id (created_by_id, assigned_agronomist_id).
  6. field_visits: Foreign key users.id, customers.id, JSON review_signals, float GPS.
  7. employee_targets: Foreign key users.id, integer targets, date boundaries.
  8. audit_events: Foreign key users.id, JSON metadata, indexed timestamps.
  9. chat_rooms: Valid room metadata, creator foreign key.
  10. chat_messages: Foreign keys chat_rooms.id, users.id (sender_id).

B. Topological Foreign Key Ordering:
Topological sorting of the Base.metadata dependency graph was confirmed:
  users -> customers -> field_visits -> attendances -> targets -> chat
No circular foreign keys exist in the schema.


2. STARTUP LIFESPAN DIALECT SAFETY
--------------------------------------------------------------------------------
The backend lifespan function in backend/app/main.py was modified:
```python
def _run_sqlite_column_migrations(conn):
    if conn.dialect.name != "sqlite":
        return
    # PRAGMA table_info is only executed on SQLite
```
On PostgreSQL, table creation is handled via Base.metadata.create_all or Alembic
migrations, and SQLite PRAGMA commands are safely bypassed.


3. RENDER MANAGED POSTGRESQL BLUEPRINT
--------------------------------------------------------------------------------
The Infrastructure as Code specification in render.yaml was upgraded:
```yaml
databases:
  - name: phytodoctor-db
    plan: free
    region: oregon
    databaseName: phytodoctor
    user: phytodoctor_user

services:
  - type: web
    name: phytodoctor-api
    runtime: python
    rootDir: backend
    envVars:
      - key: DATABASE_URL
        fromDatabase:
          name: phytodoctor-db
          property: connectionString
      - key: CREDENTIAL_ENCRYPTION_KEY
        generateValue: true
```
Render automatically manages connection string injection, database credentials,
and SSL certificates.
