     Lines 110-145:

         for table in ordered_tables:
             ...

     except Exception as e:
         print(f"[ERROR] Migration failed: {e}. Initiating transaction rollback...")

     When invoked with --dry-run, the script reads all source SQLite records,
     validates foreign key references, prepares target ORM entities in memory,
     and executes an immediate session rollback without committing to PostgreSQL.
  4. Incremental Batching & Primary Key Preservation:
     All records maintain their original UUID primary keys (e.g. user.id, visit.id),
     preserving audit event linkage, customer references, and mobile sync anchors.

4. ROLLBACK & DISASTER RECOVERY RUNBOOK
--------------------------------------------------------------------------------
Scenario A: SQLite Database Corruption on Host
  1. Stop uvicorn service: taskkill /F /IM python.exe
  2. Inspect latest backup in ./backups/:
     dir ./backups /O:-D
  3. Execute restore using CLI tool:
     python backend/scripts/backup_restore.py --restore ./backups/phytodoctor_sqlite_<TIMESTAMP>.db
  4. Verify integrity with drill:
     python backend/scripts/backup_restore.py --drill
  5. Restart backend service.

Scenario B: PostgreSQL Cloud Migration Interruption
  1. Target database transaction automatically issues ROLLBACK on unhandled exception.
  2. Zero table drops occur.
  3. Review migration log in console.
  4. Correct environment configuration (e.g., firewall, network timeout, SSL mode).
  5. Re-run migration with --dry-run first to verify connectivity.
