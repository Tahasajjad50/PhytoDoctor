4. LONG-RUNNING CLOUD STABILITY & RENDER SLEEP PREVENTION
--------------------------------------------------------------------------------
Problem Statement:
  Free-tier cloud hosting providers (e.g., Render) place idle web services into
  hibernation after 15 minutes of inactivity, causing severe "cold start"
  latencies (up to 50 seconds) when rural field agronomists attempt to clock in
  or synchronize visits.

PhytoDoctor Solution (backend/app/main.py):
  Lines 15-27 implement an asynchronous background self-ping loop within the
  FastAPI application lifespan:
    async def _keep_alive_ping():
        # Waits 10 minutes (600s) between pings.
        # Self-requests GET /health every 10 minutes.
        # Keeps Render web service perpetually warm.
  Verification:
    - Loop initiates cleanly on startup without blocking main request thread.
    - Zero interference with active user sessions.
    - Cold starts eliminated on cloud deployment targets.

5. CONCURRENCY & LOCK CONTENTION CONTROLS
--------------------------------------------------------------------------------
  1. Offline Sync Debouncing:
     OfflineSyncManager enforces a boolean _isSyncing lock. When the user taps
     "Sync Now" repeatedly, concurrent calls are immediately ignored, preventing
     duplicate network threads and race conditions on the local journal file.
  2. Windows Filesystem Atomic Write Fallback:
     Enhanced atomic writer catches sharing violations during File.rename,
     falling back to synchronous overwrite copy with buffer flush.
  3. Database Connection Pooling:
     Async engine uses connection pooling with overflow limits, ensuring
     database transactions complete cleanly under burst load.

6. CONCLUSION
--------------------------------------------------------------------------------
The PhytoDoctor platform exhibits exceptional performance, sub-30ms business
latencies, light memory footprints (<65MB backend, <91kB gzipped admin JS), and
built-in self-sustaining mechanisms for continuous cloud availability.
