1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
Field agronomist visit reports and attendance clock-ins require tamper-evident
evidence consisting of physical camera photographs and precise GPS geolocation
coordinates. This report documents the technical audit of:
  1. Camera capture and client-side photo retention.
  2. GPS coordinate validation, accuracy thresholds, and flagging rules.
  3. Direct-to-Cloudinary pre-signed cryptographic upload architecture.
  4. Media authorization, file type filtering, and quota estimations.

2. CAMERA & LOCAL PHOTO EVIDENCE LIFECYCLE
--------------------------------------------------------------------------------
Architecture:
  - Mobile Camera Plugin: camera / image_picker
  - Storage Layer: mobile/lib/core/storage/photo_storage_service.dart
  - Private Evidence Directory: getApplicationDocumentsDirectory()/private_evidence/

Verification Findings:
  1. Mandatory Evidence Enforcement:
     - Attendance Clock-In: photo_url is mandatory (min_length=5). Clock-in without
       photo returns HTTP 422 Unprocessable Entity.
     - Field Visit: photo_url is mandatory for high-confidence crop disease reports.
  2. Local Private Retention:
     Captured images are written to the application's isolated sandbox:
     /data/user/0/com.phytodoctor/files/private_evidence/<VISIT_UUID>_<FILENAME>.jpg
     Photos are never stored in public device galleries (DCIM/Pictures) to prevent
     user tampering or gallery deletion prior to synchronization.
  3. Pre-Upload Compression:
     Images are compressed client-side to target ~800KB-1.5MB per photo, maintaining
     leaf disease diagnostic fidelity while minimizing rural 2G/3G bandwidth usage.

      - Payload with gps_accuracy=65.0 submitted.
      - Response: HTTP 201 Created (Visit NOT rejected).

  - Result: PASS.

4. CLOUDINARY PRE-SIGNED DIRECT UPLOAD ARCHITECTURE
--------------------------------------------------------------------------------
Direct-to-Cloud Upload Flow:
  1. Mobile app authenticates with PhytoDoctor backend (Bearer JWT).
  2. Mobile requests signed upload parameters: POST /api/v1/media/sign-upload.
  3. Backend verifies user role and generates SHA-1 HMAC signature using
     CLOUDINARY_API_SECRET and timestamp.
  4. Mobile uploads directly from device to Cloudinary API endpoint:
     https://api.cloudinary.com/v1_1/<CLOUD_NAME>/image/upload
  5. Mobile receives secure_url and public_id from Cloudinary.
  6. Mobile submits visit payload referencing Cloudinary secure_url.

Automated Test Evidence (backend/tests/test_cloudinary_integration.py):

[TEST 1] Signed Upload Authorization Security
  - Test Target: test_signed_upload_authorization_security

  - Cryptographic Verification: Generated signature verified to match SHA-1 HMAC.
