1. ARCHITECTURAL OVERVIEW
--------------------------------------------------------------------------------
PhytoDoctor implements an uncompromising offline-first design pattern. Field
agronomists frequently operate in deep rural agricultural zones with zero
cellular coverage. The application must guarantee:
  1. Instantaneous local persistence without network blocking.
  2. Crash and process-termination resilience.
  3. Automatic corruption recovery.
  4. Non-loss retention: No local record is ever deleted before confirmed HTTP 201.
  5. Backend UUID idempotency: Duplicate submissions never create duplicate records.

Phase 5 Enhancement (Windows Filesystem Overwrite Fallback):
  On Windows OS, atomic rename of open files can trigger PathExistsException
  or FileSystemException. Phase 5 updated _atomicWriteFile to catch these
  exceptions, fall back to safe overwrite copying with stream flushing, and
  unlink the temporary file, ensuring 100% platform resilience.
