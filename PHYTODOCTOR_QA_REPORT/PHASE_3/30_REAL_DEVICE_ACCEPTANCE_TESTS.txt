2. GPS LOCATION SENSORS & ACCURACY THRESHOLD AUDIT
--------------------------------------------------------------------------------
A. 50-Meter GPS Accuracy Threshold:
   - Specification: Agricultural field scouting occurs in remote rural areas
     where satellite reception can fluctuate.
   - Verified Behavior:
     - If GPS accuracy is <= 50.0 meters, the visit status is marked 'PENDING'
       or 'VERIFIED'.
     - If GPS accuracy is > 50.0 meters, the system flags the visit for
       supervisor review ('FLAGGED_FOR_REVIEW') but **DOES NOT BLOCK**
       the agronomist from submitting the visit.
     - Rationale: Hard blocking remote agronomists due to bad weather or cloud
       cover causes data loss and field frustration. Flagging permits managers
       to review and approve legitimate visits.

B. Mock Location & GPS Spoofing Detection:
   - The Flutter mobile client inspects Position.isMocked from geolocator.
   - If mock location is detected:
     - The visit payload sets 'is_mock_location: true'.
     - Backend automatically flags the visit with review_reason:
       "SUSPECTED_LOCATION_SPOOFING".

C. Emulator vs Physical Hardware Behavior:
   - On Android Emulator: Uses telnet or Extended Controls to inject lat/long
     (e.g. Multan: 30.1575 N, 71.5249 E).
   - On Physical Device: Prompts user for ACCESS_FINE_LOCATION and
     ACCESS_COARSE_LOCATION at runtime. If location services are disabled, prompts
     user with native system dialog to enable GPS.

3. CAMERA SENSOR & CLOUDINARY MEDIA PIPELINE
--------------------------------------------------------------------------------
A. Photo Capture Pipeline:
   - Uses device camera with 1080p target resolution to balance crop detail
     with cellular bandwidth consumption.
   - Compresses raw camera frames to JPEG with 85% quality encoding.
   - Typical file size: 250 KB to 1.8 MB (well below the 10 MB system ceiling).

B. Cloudinary Upload Architecture:
   - Direct Secure Multipart Upload:
     Mobile app sends multipart/form-data to POST /api/v1/media/upload-direct.
   - 10MB Ceiling Validation:
     Enforced on client before transmission and strictly checked on backend
     via Content-Length and byte streaming limits. Files > 10MB receive HTTP 413.
   - Signed Cloudinary Parameter Generation:
     For direct client-to-CDN uploads, POST /api/v1/media/visits/{id}/upload-auth
     generates SHA-1/SHA-256 HMAC signatures using the server API secret, ensuring
     tamper-proof uploads directly to Cloudinary.
   - Association & Confirmation:
     POST /api/v1/media/visits/{id}/confirm-photo binds the public_id to the visit
     record in the database.

4. STORAGE DIRECTORY PERMISSIONS & APP LIFECYCLE RESILIENCE
--------------------------------------------------------------------------------
A. Storage Sandbox:
   - The app stores its journal file and cached images in the internal private
     directory returned by getApplicationDocumentsDirectory().
   - Path: /data/user/0/com.phytodoctor.app/app_flutter/
   - Permissions: No external storage permissions (READ_EXTERNAL_STORAGE) required
     on Android 10+, ensuring compliance with Google Play Scoped Storage policies.

B. Low Battery & OS Termination:
   - Because writes to 'phytodoctor_visits_journal.json' are atomic with disk
     sync, an abrupt kill by Android Low Memory Killer (LMK) does not leave a
     corrupted file. The .bak file protects against uncompleted writes.
